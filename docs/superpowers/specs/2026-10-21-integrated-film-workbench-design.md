# GRemote × M10V 胶卷工作台设计

日期：2026-10-21。状态：视觉方向及本书面规格已由用户确认；实施计划待评审。本文不表示无线桥、Flutter 页面或相机功能已经实现。

## 1. 目标与确认的视觉方向

交付「试卷台 + 数字胶卷」以及「无线装卷与双向同步」，形成试色、选卷、装卷、拍摄、按卷整理和联系印样导出的闭环。

用户于本次会话回复“可以的”，确认以沉浸取景为默认的深绿黑、暖金、米白视觉方向。接触印样作为试卷台的比较模式保留。沿用现有 App 的首页、拍摄、图库、暗房全局导航；首页新增胶卷工作台入口，工作台内部使用试卷台、数字胶卷、相机胶卷三个分区。拍摄页和图库提供返回当前胶卷的入口。

视觉参考：[已确认视觉稿](../../design/film-workbench/2026-10-21-visual-board.png) 与 [可交互原型](../../design/film-workbench/2026-10-21-prototype.html)。原型的 CSS 效果、模拟照片与同步进度全部替换为真实业务状态。场景示例图为 AI 生成，不能作为相机出片或色彩测试样本。

首个设备验收目标为 GR III 2.10 + Android；保留现有 iOS 工程可构建性，iOS 相机连接按现有平台能力显示状态。IIIx、IV 需独立适配和验收，不能从 III 的通过推导兼容。未连接相机也能选卷、对本地 JPEG 试色、管理胶卷和导出印样。

## 4. 试卷台

### 4.1 输入和预览

支持内置示例、本地 JPEG、相机取景流三种输入。示例为明确标识的体验素材；本地文件使用已有媒体访问；取景流复用现有连接和帧解析，不另建持续 HTTP 视频连接。用户未连接相机时仍可使用前两种。

默认单图拖动原色/效果分界线；比较模式同时显示原色与三种已选胶卷。仅作用于手机预览，不因浏览或调参改变机内状态。原图、预览像素与操作历史独立；拖动分界线只改变裁剪区域，不重新渲染。

从 M10V 目录/能力真源生成带哈希的手机清单、图标和参数描述。抽取可在主机编译的 M10V 纯渲染源码及其明确依赖，形成有版本指纹的 App 本地库；不把相机服务地址、menu/FS 代码链接到 App。保留来源与许可证文件。适配器负责 RGBA 与 M10V 的 Y/CbCr422 平面转换、pitch、有效区域及回转，色域和舍入用固定向量验证。已有手机 `.cube` 流程继续可用，但不冒充原生完整胶卷算法。

取景输入与机内 JPEG/ISP 基底不同，界面保留“近似预览”。颗粒、光晕等空间效果在预览分辨率适配后仍不承诺逐像素一致。针对已带胶卷色彩的照片显示来源提示，默认不再次套用完整色彩，用户可明确选择叠加。

### 4.2 响应性

预览在后台 isolate/native worker 执行；实时输入队列只保留最新帧，最多一个执行任务、一个待执行任务。连续拖动合并请求，旧 generation 的结果不更新 UI。长边初始上限 960，低内存或处理耗时增加时降低到 640。切换颜色后先出色彩结果，再补空间质感；两个阶段都绑定相同配方指纹。缓存预算上限 48 MiB，离开页面释放输入与预览缓存。

设计目标为移动端手势反馈不等待图像任务；实际帧率、调参延迟、温度和内存峰值列入真机测量，不把目标数字写作结果。动画采用 180–230ms 页面过渡、280ms 弹层；尊重减少动画设置，触控区域至少 44 逻辑像素，验证 320px 宽度和横屏返回。

### 4.3 配方

`FilmRecipe` 包含 schemaVersion、filmId、catalogHash、rendererHash、参数、可选自定义内容哈希和本地名称。参数以协议原值存储，仅展示层翻译。新增配方不可通过改名变成另一机型支持；不支持项明确显示并阻止装卷，不静默丢弃。

## 5. 数字胶卷

### 5.1 数据与状态

新增数据库 v4，采用增量建表保留已有 v1–v3 数据。

- `film_recipes`：不可变内容指纹、来源、schema、完整配方 JSON；编辑产生新指纹。
- `film_rolls`：ID、名称、目标张数、封面引用、默认配方指纹、创建/结束时间、状态；状态为 open、closed、archived。同一时刻全 App 最多一个 open 胶卷，切换通过事务先关闭或取消当前卷。
- `film_roll_items`：卷 ID、本地媒体引用或 cameraKey、每张配方快照、来源、确认状态、拍摄/发现时间。RAW+JPEG 一组占一张；后到文件补入组内。
- `camera_sync_baselines`：相机本地身份、最近共同基线、schema/catalog/renderer、revision、内容哈希。
- `camera_sync_operations`：requestId、baseRevision、目标 patch、状态、结果摘要；允许 crash 后恢复查询。

相机身份由已配对的伴侣服务 instanceId 与本地配对记录关联，不在云端存储完整序列号。不依赖只含文件名的全局键；cameraKey 包含相机身份、存储标识、目录、baseName、可取得的拍摄身份，必要时加文件内容指纹，处理卡格式化和编号复用。

目标张数为创作提示，不拦截快门。达到目标时提示可结束或继续拍。结束后仍可浏览、导出和显式补入漏归档照片；不会重新开启拍摄会话。

### 5.2 自动记录与离线补入

订阅现有已确认文件发现事件，不按快门请求次数计数。连接期间的 App、机身和程序拍摄均可归档，但必须有文件身份；按请求冻结的配方与文件匹配后确认。仅有 UI 选卷、超时或 `captureId` 变化不足以证明照片保存。

原厂协议不能确认本张私有胶卷时，记录 recipeConfidence=unverified，界面不伪造真实配方。配套桥提供稳定拍摄身份和本张快照时记录 cameraConfirmed。发生连接代际变化或机身改卷时，不把手机旧配方写给新照片。

断线重连后比较文件集合，按相机身份和有效时间范围提出“发现未归档照片”，由用户选择补入及配方；不把断线期间所有新增文件自动归入当前卷。锁屏/后台采集不作为首版保证，定位沿用现有授权与生命周期。

### 5.3 冲洗和分享

“结束并查看印样”生成独立 JPEG 联系印样，按每页最多 24 张分页，输出到现有导出目录/系统相册；逐张解码，不一次持有整卷原图。保留缺失/读取失败的位置并提示，允许重试，单张失败不取消其他任务。

已由 M10V 处理的 JPEG 默认只加版式与元数据，不再次套色。自选精选集和可导入的配方卡属于同一交付范围。配方卡仅含配方与兼容声明，默认不含精确位置或密钥；未知 schema 拒绝导入并保留当前状态。

## 6. 无线装卷与双向同步

### 6.1 架构选择

采用专用的相机本地伴侣服务，复用原厂 Wi-Fi 网络，不修改原厂 webapid 路由或开放通用 Shell。日常装卷无须重刷固件；首次需要安装匹配的 M10V 支持候选和 SD 启动组件。启动组件采用 GRKit 已证实的 TTL/lcmd 启动方式，独立服务只承担网络、认证、协议和消息传递，不安装 GRKit 菜单或成像 runtime。

相机端分为 Linux 服务、版本化消息桥、RTOS 配置执行者三层。网络进程不直接改 AppData、照片卷或全局当前配方，也不从 Linux 调 RTOS 函数地址。相机存档与 SD 写入仍由相机侧已有文件 API 执行。

消息桥使用有所有者的驻留分配和有界请求/响应槽。地址、容量、目标和当前构建全部验证；地址由生成 target 描述与启动协商取得，不在 App 或插件硬编码。发布顺序、读写屏障、alias cache 同步、关机与脚本生命周期必须有独立适配。GRKit 安装时的 sync_alias 不能自动证明持续双向数据的缓存一致性。

RTOS 消费者必须在经证实的配置/UI 所有者任务中被唤醒，统一串行化本地菜单与远程配置提交。禁止在 JPEG 捕获 Hook 中处理网络、保存设置或写 SD。现有源码没有可直接认定满足要求的通用消费者入口，因此实现顺序先完成只读往返探针和该所有者/唤醒入口证明，再启用写入。若无法证明，此设备报告 bridgeUnavailable，继续保留手机功能并如实交付诊断；不得以模拟服务或仅下载配置文件冒充无线完成。

本方案不要求把全部 M10V 迁移到 GRKit。开启/撤除 SD 组件不覆盖用户 STARTUP 逻辑，不热杀驻留脚本；仅在关机后更新组件。

### 6.2 发现、配对与传输

原厂相机探测成功后，App 只向同一已绑定 Wi-Fi、已确认相机主机的固定伴侣端口 18743 探测 `/m10v/v1/capabilities`。新增独立 `CompanionTransport`，Android 继续使用该 Network 的 socket factory；拒绝任意主机、重定向和任意端口输入。原厂 CameraTransport 与其恢复行为保持独立。

测试包生成独立 256-bit 随机配对密钥，配对信息由用户导入到 App；密钥不提交仓库、不进入日志或截图，App 存入平台保护存储。服务在已核实的相机 Wi-Fi 接口可用后才绑定该接口。协议使用认证请求；配对失败、构建不匹配或 bootId 改变时重新核对能力和基线。上线前做认证、重放和请求边界测试，不开放任意路径文件上传。

网络预算：JSON 请求上限 16 KiB；二进制分块最大 16 KiB、单胶卷记录上限 12,288 字节，服务总暂存预算 64 KiB；并发写操作仅一个。活跃工作台状态最多每 2 秒刷新一次，应用回前台/同步前立即刷新；后台停止轮询。拍摄、原图传输或相机忙时推迟写操作；网络服务不阻塞快门。

### 6.3 版本化 API 合同

以下为新建私有 API，不是对原厂接口的现有能力声明。

| API | 行为 |
| --- | --- |
| `GET /m10v/v1/capabilities` | protocol、model、firmware identity、buildId、bootId、instanceId、schema/catalog/renderer 哈希、slotCount、支持的读/写/上传能力与参数范围 |
| `GET /m10v/v1/state` | RTOS 验证过的五槽、当前槽、相关全局设置、revision、配置哈希、busy、状态新鲜度 |
| `POST /m10v/v1/operations` | 有界、带 requestId 和 baseRevision 的变更请求；返回操作身份和 pending，不能当作已提交 |
| `GET /m10v/v1/operations/{requestId}` | queued/applying/committed/rejected/unknown；committed 含读回的完整状态及 revision |
| `POST /m10v/v1/films/stage` | 暂存一条通过合同的自定义记录；校验模型、长度、稳定 ID 和内容哈希，不激活槽位 |
| `PUT /m10v/v1/films/stage/{uploadId}/chunks/{index}` | 有序有界分块、内容哈希、幂等；上传中断不影响当前卷 |
| `POST /m10v/v1/films/stage/{uploadId}/verify` | 相机侧持久化与完整读回校验，返回可引用的已验证内容身份 |

变更示例：

```json
{
  "protocol": 1,
  "requestId": "client-generated-128-bit-id",
  "bootId": "negotiated-boot-id",
  "baseRevision": "opaque-camera-revision",
  "catalogHash": "negotiated-catalog-sha256",
  "rendererHash": "negotiated-renderer-sha256",
  "patch": [{"slot": 0, "filmId": 33, "grain": 2}],
  "activateSlot": null
}
```

槽位协议值 0–4，展示为 01–05。`activateSlot=null` 只安装/调整，不切换当前拍摄卷；用户可明确勾选“装入后使用”。首次装卷入口默认装入并使用，确认页明确显示此选择。浏览和高亮从不写入。当前槽切换需正式 tone setter 及读回确认，不能只改手机选中样式。实施计划将装入和激活拆为两次受确认操作：先保存配置，再切换当前槽；激活失败显示“已装入，切换失败”并保留真实状态，不承诺跨存档和原厂 tone 服务的原子回滚。

缺省字段保持原值；未知字段/无效组合拒绝整次变更。响应错误保留结构化 code：unauthorized、unsupportedProtocol、unsupportedModel、incompatibleRenderer、invalidRecipe、busy、revisionConflict、storeFailed、readbackMismatch、bridgeUnavailable。中文仅在 App 展示层翻译。

### 6.4 提交、一致性与失败

1. 读取一致快照，取得 bootId、opaque revision 与内容哈希；App 保存为共同基线 B。
2. 手机本地调整形成 L，重新读取相机 R。对 B/L/R 做逐字段三方合并：仅一端改动直接列入差异；两端相同无需操作；同字段不同值必须用户选择。
3. 选择“保留两份”先产生独立本地配方，不擅自占用其他机内槽。未知参数或新目录保持只读，不用旧 normalizer 擦除。
4. 用户确认后发送限定 patch。RTOS 执行者在同一串行化域再次检查 revision/busy，验证全部字段与内容身份，在临时状态中完成修改，一次提交现有双记录，并完整读回；验证及提交前失败保持原状态。写后持久化结果无法确认时返回 unknown，重新读取核对，不能承诺未被证实的回滚。
5. 仅收到 committed 且读回相符后更新共同基线和 UI。revision 绑定构建、bootId、有效 journal sequence 与完整配置哈希，避免时钟排序与序号回绕歧义。
6. 网络超时显示“结果待核对”，同一 boot 内以相同 requestId 查询/重试；相同 ID 不同负载拒绝。重启后服务不假称保留去重缓存，App 重新读取比较后让用户确认，不盲目重放旧操作。

现有本地菜单操作也须进入同一提交域，不能只在网络执行者入口加锁。不得通过在旧状态上连续调用多个立即保存的 setter 模拟原子提交。单次变更要么整体提交，要么整体拒绝，不允许半套质感被保存。

自定义胶卷沿用 M10V 当前合同。仅上传受支持的记录/数据，不传可执行插件。未被当前/排队捕获引用的 bank 才能被替换；引用无法确认时返回 busy。持久化失败和断电不得切换到半写入胶卷；旧有效卷与其他槽位不变。

### 6.5 App 状态呈现

连接状态为 offline、connecting、unsupported、ready、busy、error；同步操作为 draft、conflict、queued、applying、verifying、synced、unknown、failed。收到网络 2xx 不直接进入 synced。未安装组件显示“相机暂不支持无线装卷”并提供匹配安装说明，选卷与胶卷管理仍可用。原型中的常驻“已同步”替换为有共同基线和新鲜读回证据的状态。

## 7. 模块边界

GRemote 新增 `lib/film/`（目录/配方/预览/胶卷/仓储）、`lib/camera/companion/`（协议/能力/同步/传输）和 `lib/features/film_workbench/`（三个页面及弹层）。沿用 Riverpod 与 GoRouter；UI 不直接解析二进制状态或发起平台请求。数据库迁移由 GRemoteDatabase 统一拥有。印样导出接入现有队列及媒体发布，而非另建覆盖原片的通道。

M10V 新增可主机测试的 protocol/command/transaction 核心、目标适配器、消息桥、Linux 服务和 SD 打包；具体 RTOS 地址只能由受保护的目标描述和构建审计拥有。新增受审计的功能选项，默认不影响已有普通构建。网页及 CLI 对相同配置使用同一构建链和 receipt。

共享目录、参数 schema、状态 fixture、错误码和哈希规则从一个 registry 生成 Dart/C/服务测试数据。App 发行包固定可预览的渲染指纹；相机较新版本的未知卷仍可读取名称和状态，但不错误地显示兼容预览或允许旧格式覆盖。

## 8. 分阶段交付与验收

阶段是同一需求的实施顺序，不缩减最终范围。

1. 合同与可行性：固定源码基线、生成目录及 fixtures；完成 Linux→消息桥→RTOS 只读往返、消费者所有权/生命周期/缓存证明；保存离线证据，形成可识别相机探针包。用户设备步骤未执行时明确标记。
2. 手机工作台：按已确认视觉实现离线试卷、真实预览、数字胶卷、印样和配方卡；使用 fake companion 测失败路径，但测试模式不能伪装为真实设备。
3. 无线读写：认证、能力发现、正式 RTOS 提交、自定义数据暂存、三方合并、装入/激活与完整读回；接通真实平台传输。
4. 集成测试包：Android APK + 对应 GR III 支持候选/SD 组件 + fixture/恢复/验收说明，附版本、SHA-256、source/config fingerprint 和已执行检查。设备验收通过前不宣称功能实机完成。

必须验证：

- 数据库升级保留既有图库、配方、位置和导出记录；卷/照片去重、晚到 RAW、卡编号复用、跨相机、断线补归档、不可变历史配方。
- 纯渲染固定向量与 M10V 对照、奇数尺寸/pitch/边界、取消与代际切换、内存预算；320px 窄屏、横屏返回、减少动画、实际主题。
- 协议畸形输入、认证、超限、重放、重复/冲突请求、错误机型/渲染版本、三方合并、无损保留未知字段。
- 相机事务坏 journal 回退、写失败/读回不符、断线、重启结果未知、本地同时改动、拍摄 busy、排队快照不变、自定义 bank 引用保护。
- 真实设备：同机型/同卡/同格式的连接与重连、读五槽、装卷及首张 JPEG、参数变化回传、冲突选择、RAW+JPEG、连拍/回放、原厂参数恢复、关机重开和 SD 组件撤除；测量预览帧率、手势响应、装卷耗时与机内拍摄耗时。

运行适用的 Flutter/native/Android 检查，M10V 全量 npm 与相关 Python/ARM/最终产物审计；记录 fixture 缺失与 skip，不能修改旧断言掩盖回归。设备端源码 revision 与脏文件指纹共同记录。保留当前 A/B 已知问题并避免将其修复混入本需求。

## 9. 发布与恢复

遵循用户指定 grkit-development：开发回归 → 可识别测试包 → 用户明确验证 → main/GitHub/宝塔。当前视觉确认不授权刷机、启用设备脚本或生产发布。

恢复说明逐包绑定目标和哈希；SD 组件正常撤除必须关机后仅移除本功能拥有的文件和 include，保留用户其他脚本与照片。停止服务不清空 M10V journal；关闭无线扩展后机内原有胶卷功能继续工作。固件回退使用既有经过约束的官方恢复路径，不能承诺任意异常均可恢复。

## 10. 规格评审重点

用户确认的是：视觉方向保留；首个目标为 GR III + Android；首次装配配套相机支持后日常无线装卷；机身改动可回传，冲突显式选择；数字胶卷按已确认照片归档；预览始终标明近似效果；正式发布等待设备验收。

书面规格确认后编写分步骤实现计划并执行选定的实现方式。无线桥在设备上仍有必须证明的低层条件；这些条件是明确的验收门槛，不会由 UI、主机模拟或 SD 启动成功代替。
