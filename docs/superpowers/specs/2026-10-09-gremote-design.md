# gremote — RICOH GR III 专业伴侣 App 设计

## 1. 产品定义

`GRemote` 是面向 RICOH GR III 用户的 Android 专业伴侣 App。此文档最初使用旧项目名，现按品牌名称更新；相机固件中的主机名属于设备协议，不随 App 改名。

V1 仅正式支持：

- 相机：RICOH GR III，不含 GR IIIx、HDF 或其他 PENTAX/RICOH 机型；
- 固件：用户提供的 GR III 2.10 官方固件；
- 固件文件：`fwdc239b.bin`；
- 固件 SHA-256：`d6a3c9c288d784080e7b283222ecdd8752adfeed6faa36dab44f73115354bfd4`；
- 手机：小米 14，Android/HyperOS；
- 交付：本机私有签名的 `arm64-v8a` release APK，侧载安装；
- 语言：中文为主，保留 ISO、LUT、DNG、EV 等摄影术语；
- 数据：本地优先，不设账号和服务器；配方与 LUT 通过文件导入、导出和系统分享。

包名使用 `com.izhaoo.gremote`。项目采用 GPL-2.0-only，移植 `gr-custom-tool` 代码时保留许可证与署名。官方固件、用户照片、签名文件和凭证不得进入 Git 或 APK。

## 2. V1 范围

### 2.1 日常相机能力

- BLE 配对、自动重连、唤醒、休眠和轻快门；
- BLE 引导开启相机 AP，Android 自动连接并绑定无互联网 Wi-Fi；
- 手动 Wi-Fi 连接兜底；
- 相机状态：机型、序列号、固件、电量、温度/过热、SD 卡、剩余张数、当前参数；
- 自动同步相机时间与时区；
- 实时取景、触控对焦、半按 AF、拍照和录像；
- 单拍、连拍、自拍、包围、相机间隔和手机定时/间隔拍摄；
- 曝光模式、Av、Tv、ISO、曝光补偿、白平衡、测光和对焦模式；
- JPEG、DNG、MOV 的浏览、选择和下载；
- 手动下载，以及可选的“连接后同步未导入文件”；
- GPS 拍摄会话、BLE 实时写入与下载后轨迹补写。

### 2.2 创作能力

- 拍摄预设和色彩配方两层模型；
- 原厂固件下同步开放参数，不开放的参数展示手动菜单路径；
- Live View GPU 实时 LUT，效果只作用于手机预览；
- 内置原创 LUT，导入 17/33/65 点 `.cube`；
- DNG/JPEG 专业全局暗房；
- 三套可无损切换的边框；
- 原始文件永不覆盖，渲染结果导出为 JPEG 副本；
- GR 下载图库加系统照片选择器外部导入。

### 2.3 实验固件能力

- 严格识别官方固件并创建不可变备份；
- 证明无修改重包与原文件逐字节一致；
- 生成最小版本候选与回退候选；
- 在 INITFS 中加入 Linux 用户态色彩配方桥接；
- 输出候选 BIN、构建 manifest 和独立验证报告；
- App 不向相机上传固件，不触发升级，也不操作 SD 卡。

### 2.4 不进入 V1

- iOS；
- GR IIIx、HDF 或其他固件版本的正式兼容；
- 云账号、社区、配方商城和跨设备同步；
- 局部画笔、径向/线性蒙版、AI 蒙版与生成式移除；
- 相机原生 LOG；
- 胶片测光、Zone 实景、负片翻拍反相与胶卷日志回填。

胶片测光、Zone 实景、负片翻拍反相与胶卷日志回填进入 V2 路线。iOS、更多机型、云服务和局部/AI 编辑没有承诺版本。除非未来相机固件原生提供，否则任何版本都不能宣称支持 GR III 原生 LOG。V1 的 `gremote Log` 是 DNG 线性数据进入 LUT 前的内部标准化中间空间。

## 3. 固件分析证据与可行性

官方 BIN 已被解码为 14 个分区：

`BOOTPARA, DRAMPARA, PARTPARA, M0, BOOT, RTOS, LINUX, INITFS, SRIC, CPU, SHELLCMD, ICONBIN, FDRVPARA, RES`

关键证据：

- INITFS 内运行 `bled`、`webapid`、`camctld`、`mtpd` 和 `libcamera-controller.so`；
- `webapid` 暴露 `/v1/liveview`、照片列表/信息/传输、拍照、取消、合成、对焦、参数和 WebSocket 变化通知；
- `/v1/liveview` 返回 `multipart/x-mixed-replace` JPEG 流；
- 照片接口支持 JPEG、DNG、MOV，传输尺寸含 `full`、`xs`、`thumb`；
- BLE 固件包含相机电源、GPS、WLAN、快门、光圈、快门速度、ISO、曝光补偿、白平衡、驱动和状态通知；
- `mtpd` 含 Image Tone、饱和度、色相、对比、高光/阴影、锐化等广泛 PTP 属性映射；
- `libcamera-controller.so` 导出通用属性读取与设置接口；
- 未发现 GR III 原生 LOG 证据；
- 未发现 HTTP `Range`/`Content-Range` 证据，因此不能承诺单文件字节级续传。

结论：下载、遥控、GPS 和基础参数同步在原厂协议上可实现；完整色彩配方同步需要实验桥接；RAW 暗房在手机侧实现。

## 4. 总体架构

采用 Flutter UI + Kotlin 设备层 + C++ 图像核心的分层混合架构。

### 4.1 Flutter / Dart

负责：

- Material 3 自定义 UI、路由、动画和无障碍；
- Riverpod 状态与依赖注入；
- 四 Tab 信息架构；
- 相机 HTTP API 客户端与能力协商；
- 连接、拍摄、下载和导出任务编排；
- SQLite 元数据、配方、编辑图和轨迹；
- 固件容器编解码、补丁计划与验证编排。

### 4.2 Android / Kotlin

通过 Pigeon 生成类型安全平台接口，负责：

- BLE GATT 扫描、配对、读写、通知和重连；
- `WifiNetworkSpecifier`、无互联网 Wi-Fi 请求与进程网络绑定；
- 相机专用 HTTP Socket 绑定，避免请求误走蜂窝网络；
- GPS 拍摄会话前台服务；
- 下载前台服务与系统通知；
- MediaStore、照片选择器、文件分享和 Android Keystore；
- HyperOS 后台权限与省电白名单引导。

### 4.3 C++ 图像核心

通过 Dart FFI 暴露稳定 C ABI，负责：

- LibRaw DNG 解码；
- 32 位浮点线性 RGB 管线；
- 白平衡、曝光、高光阴影、曲线、HSL 与色彩分级；
- 降噪、锐化和镜头校正；
- `gremote Log` 转换与 `.cube` 四面体插值；
- 三种边框合成、文字布局和全分辨率导出；
- 瓦片渲染与内存预算。

Live View LUT 使用 Flutter FragmentShader，在 GPU 上处理相机 JPEG 预览，不经过 RAW 引擎。

### 4.4 隔离的固件实验室

固件构建位于独立 feature，普通 App 流程不引用其服务。其输入、输出、缓存和日志使用独立目录。C++ 图像崩溃、固件构建失败或实验桥接不可用都不能破坏相机连接与图库数据。

## 5. 信息架构与视觉

底部四个入口：

1. 首页：连接、状态、GPS 会话、BLE 快门和快捷任务；
2. 拍摄：Live View 与全部遥控控制；
3. 图库：相机目录、下载任务、本地 GR 图库和外部导入；
4. 暗房：RAW/JPEG 编辑、LUT、边框和配方。

设置从首页右上角进入；实验室从“关于 gremote”连续点击主机名 7 次后解锁。

视觉采用“杂志式静奢”：

- 深夜蓝背景与低对比层级；
- 克制的金色描边和状态强调；
- 衬线大标题、中文无衬线正文、等宽参数；
- 大留白、细分割线和摄影画册式构图；
- 遥控页允许使用精密仪器式刻度与参数控件；
- 普通页面锁定竖屏，拍摄页支持横屏全画面；
- 动画 160–420 ms，支持共享元素、参数刻度和触感反馈；
- 遵循系统“减少动画”，确保 120 Hz 设备滚动和导航无明显掉帧。

## 6. 相机连接状态机

固定状态：

`idle → scanning → pairing → bleReady → waking → apStarting → wifiRequesting → wifiBound → probing → ready`

断开状态细分为 BLE 丢失、Wi-Fi 丢失、相机忙、相机关机和 Android 拒绝网络。

连接过程：

1. BLE 扫描只接受匹配的 RICOH GR 身份；
2. 系统完成配对，读取机型、序列号、固件和电量；
3. 从 BLE 读取 SSID 与密码，密码只存 Keystore；
4. BLE 开启相机 AP；
5. Kotlin 请求 Android 连接无互联网 Wi-Fi；
6. 只将相机 HTTP client 绑定该网络；
7. 调用 `/v1/ping`、`/v1/props` 和能力探测；
8. 合并原厂能力与实验桥接能力，进入 ready。

每一步有独立错误码、超时、有限重试和修复建议。BLE 使用指数退避；Wi-Fi 丢失后先经 BLE 判断相机状态，不循环弹系统授权框。手动连接入口跳过第 3–5 步。

## 7. 拍摄与实时取景

- 解析 multipart JPEG，丢弃不完整帧，后压优先，避免延迟不断累积；
- 竖屏提供参数与画面平衡布局，横屏提供沉浸取景和可收起控制栏；
- 点击画面换算归一化坐标并发送对焦请求；
- 半按 AF 与释放为可取消状态，不把 UI 按压事件直接映射成重复 HTTP 请求；
- 参数控件以 `/v1/props` 返回的支持列表为准；
- 连拍、自拍、包围和间隔任务显示剩余时间与拍摄张数；
- 手机间隔拍摄由前台任务驱动，防止息屏后被系统暂停；
- BLE 轻快门不启动 Wi-Fi，支持 App 快捷入口；
- 过热、低电量、SD 卡不可写和相机 busy 时阻止冲突操作。

## 8. 下载与图库

- 先加载目录和缩略图，不阻塞原图传输；
- 相机媒体使用 `storage/dir/file` 组成稳定远端 ID；
- SQLite 保存远端 ID、大小、格式、拍摄时间、下载状态与本地 URI；
- JPEG、DNG 和 MOV 均可下载；
- 自动同步只选择远端 ID 未入库且符合用户格式规则的媒体；
- 任务按文件持久化，已完成文件不重下；
- 因原厂 HTTP 未确认 Range，当前文件中断时从头重试；
- 下载先写沙箱临时文件，验证 Content-Length/已知远端大小后再发布 MediaStore；
- 同名文件以远端 ID 去重，不覆盖用户已有照片；
- 熄屏下载使用前台服务，可暂停、取消和失败重试；
- MOV 下载前显示预计时间、空间占用和 Wi-Fi 断开风险。

## 9. GPS 与自动对时

用户点击“开始街拍记录”后：

- 启动有常驻通知的 Android 前台定位服务；
- 按位移、时间和精度阈值保存本地轨迹；
- BLE 可用时按节流策略将 WGS84 纬度、经度、高度和 UTC 采集时间写入相机；
- 连接相机时自动同步日期与时区，并记录时钟偏差；
- 停止会话后立即停止后台定位和 BLE 写入。

下载后，若媒体没有坐标或拍摄时断连：

1. 使用 EXIF 时间加已记录的相机时钟偏差；
2. 在轨迹中寻找时间邻近点；
3. 满足最大间隔与精度门槛时线性插值；
4. 只在导出副本写入 GPS；原始 DNG/JPEG 不覆盖；
5. 无可靠匹配时保持空值并提示用户。

精确 GPS 不写普通日志。诊断包默认移除坐标，用户可选择附带模糊定位。

## 10. 配方模型

### 10.1 拍摄预设

包含曝光模式、Av、Tv、ISO、曝光补偿、白平衡、测光、对焦、驱动、自拍、文件格式和 JPEG 尺寸。

同步流程：

1. 读取当前设置和支持值；
2. 生成目标 diff；
3. 标出不支持、只读和将被修改项；
4. 用户确认；
5. 按模式 → 文件 → 曝光 → 白平衡 → 测光/对焦 → 驱动顺序写入；
6. 每项回读；
7. 失败即停止，尝试恢复本次已修改项并输出逐项结果。

### 10.2 色彩配方

包含 Image Tone、饱和度、色相、Key、对比、高光、阴影、锐度、颗粒、清晰度、Shading 和滤镜色调。

- 原厂 API 可写项直接同步；
- 不可写项显示相机菜单路径和目标值；
- 实验桥接通过能力协商且版本匹配后，才开放完整一键同步；
- “相机平淡配方”是普通 GR 配方，不宣传为 LOG。

### 10.3 文件格式

`.gremoterecipe` 是 UTF-8 JSON，包含 schema 版本、配方类型、名称、适用机型、最低/最高固件、参数、创建来源和内容摘要。导入时验证 schema、类型和值域；未知字段保留但不执行；分享文件不得包含相机密码、序列号或 GPS。

## 11. 专业全局暗房

非破坏编辑顺序：

`RAW/JPEG 输入 → 线性化与相机色彩 → 白平衡 → 曝光/高光阴影 → 曲线 → HSL → 色彩分级 → 降噪 → 锐化 → 镜头校正 → gremote Log/LUT → 边框 → 输出变换`

功能包含：

- 相机白平衡、自动白平衡、色温与色调；
- 曝光、高光、阴影、白色色阶、黑色色阶；
- RGB 主曲线与单通道曲线；
- HSL 八色区；
- 阴影、中间调、高光色彩分级；
- 色度/亮度降噪、锐化与半径；
- DNG 元数据驱动的畸变、暗角和色差校正；
- `.cube` LUT 强度、前后对比、复制/粘贴参数和批量导出。

V1 不含局部蒙版与 AI。编辑图存参数而非中间大图。交互预览使用屏幕分辨率缓存，停止调节后刷新高质量预览，导出使用瓦片全分辨率渲染。内存紧张时降低并行度，不降低最终输出质量。

## 12. 边框与导出

三种内置边框：

1. 经典相机白边，默认；
2. 街拍版暗蓝金；
3. 胶片接触印样。

所有边框可随时无损切换。自动信息包括机型、等效焦距、光圈、快门、ISO、日期、GPS 地名和配方；字段可隐藏，标题与地点可编辑。

导出规则：

- 原件永不覆盖；
- 默认输出原始像素尺寸的 JPEG 副本；
- 可选社交尺寸与质量；
- 保留允许保留的 EXIF；GPS 默认去除，导出时可选保留；
- DNG 不写边框，只将渲染结果导出 JPEG；
- 导出写临时文件，完成后原子发布到 MediaStore；
- 分享使用系统 Sharesheet。

## 13. 实验固件设计

### 13.1 入口与输入门禁

实验室隐藏入口连续点击主机名 7 次。首次进入展示不可跳过的风险说明。

仅接受精确官方基线。校验完整文件哈希、长度、项目号、容器校验、帧解码长度、分区顺序、分区哈希、版本副本和启动布局。任一断言失败时只显示诊断，不允许构建。

### 13.2 构建门禁

1. 保存内容寻址、只读的官方备份；
2. 解包后无修改重包，要求与原始 BIN 逐字节一致；
3. 生成只改已证明版本字段的最小候选；
4. 用户按清单完成识别、启动、菜单、拍摄、对焦、存储、回放、关机和回退实测；
5. 门 3 通过后才允许生成 Linux 用户态桥接候选；
6. 独立解析输出，比较所有目标和非目标区域；
7. 输出候选 BIN、manifest、验证报告和回退候选。

候选状态为 `offline_verified`、`hardware_testing`、`hardware_verified`。未完成真机清单前，界面固定显示“实验候选／未实机验证”，禁止声称不会变砖。

### 13.3 Linux 用户态桥接

只修改 INITFS，不修改 RTOS。桥接进程调用既有 `libcamera-controller.so` 的通用属性读取/设置接口。

安全约束：

- 仅绑定相机 AP 接口；
- 仅暴露版本、能力、读取配方和应用白名单配方四类操作；
- 属性 ID、类型和值域由固件版本白名单固定；
- 不提供任意属性、内存、Shell、文件上传或固件写入；
- App 先验证桥接协议与固件 build ID；
- 桥接生成随机 nonce；两端以相机当前 Wi-Fi passphrase 和桥接 build ID 经 HKDF-SHA256 派生会话密钥，再用 HMAC-SHA256 认证带单调计数器的请求；桥接从既有相机属性读取 passphrase，App 通过 BLE 获取并存 Keystore，密钥不硬编码也不通过桥接接口传输；
- 写入按事务计划逐项回读，失败后尝试恢复快照；
- 桥接不可用时自动退回原厂 API 与手动菜单指导。

### 13.4 构建报告

manifest 至少包含输入/输出 SHA-256、源码提交、工作区状态、工具版本、候选类型、补丁清单、变化分区、变化范围、非目标一致性、回读结果和硬件状态。日志只记录哈希和地址摘要，不记录固件原始字节。

## 14. 错误模型与安全

错误类型：

- `retryable`：BLE/Wi-Fi 超时、临时 busy、下载中断、定位短暂不可用；
- `userActionRequired`：权限、HyperOS 省电、系统网络确认、空间不足、SD 只读；
- `unsupported`：相机或固件不提供能力；
- `fatalGate`：固件身份不匹配、重包不一致、补丁越界、验证失败。

用户错误页必须给出阶段、对象、错误码、原因和下一步，不能只显示“失败”。

敏感信息约束：

- Wi-Fi 密码只存 Android Keystore；
- 不记录精确 GPS、照片内容、固件字节或签名口令；
- release 日志默认 INFO 且脱敏；
- 用户主动导出的诊断包含状态时间线、手机/相机/API 版本和错误码；
- Android 签名 keystore 与口令不提交 Git；
- 官方 BIN 不打包、不上传、不提交。

## 17. 开发与发布门禁

内部顺序：

1. 原厂连接协议门禁；
2. 核心相机功能门禁；
3. 创作功能门禁；
4. 固件最小候选与桥接门禁；
5. release 发布门禁。

虽然 V1 最终一次性对外交付完整 APK，但每个内部门禁必须有可安装测试 APK 和真机结果。开发可并行，验收按序：不依赖相机的模块可以提前开发和独立测试，但任何后置门禁不得早于前置门禁判定通过。

V1 完成条件：

- 自动化测试通过；
- release APK 可在小米 14 安装启动；
- 原厂模式真机清单逐项有结果；
- 核心功能没有未披露的阻塞缺陷；
- 实验固件与普通工作流隔离；
- 未通过实机验证的桥接明确标记为实验，不影响正式功能完成；
- 源码、第三方许可和 GPL 分发要求完整；
- 官方固件、照片、凭证和签名材料均未进入 Git 或 APK。
